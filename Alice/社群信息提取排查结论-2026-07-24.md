# 同步：飞书 / 微信群信息提取排查结论（2026-07-24）

## 背景与目标

想让 Alice 长期自动读取社群聊天，做收集、整理、总结。第一个试点是飞书「Alice 体验反馈群」。靠人工每天截图不现实，需要一条技术通道。

## 今天做了什么

1. 完成飞书 user 身份授权（第一次授权链接过期，重发后第二次成功）。确认登录账号就是「有语」本人，授权本身没问题。
2. 用 API 排查为什么读不到目标群：群列表接口只返回 9 个内部群；按群名、关键词搜索均无结果；通过消息搜索间接摸到几个 chat_id，但拿这些 id 直查群详情全部返回空。

## 根因

目标群是「外部群」（跨租户群）。飞书平台对第三方应用隔离外部群，这是平台级限制，跟授权范围、跟用户在不在群里都无关。具体表现：

- 群列表 API 不返回外部群
- 消息搜索 API 搜不到外部群里的消息
- 用 chat_id 直查群详情返回空

## 方案评估

- **截图 / 复制**：不现实，排除。
- **机器人加群 + 订阅事件**：机器人只能读自己被拉进的群，第一步必须把它加进群。新消息的事件订阅相对可能走通，但历史消息能否批量读全，受外部群自身的机器人权限和跨租户策略限制，没实测过，不能打包票。
- **微信侧**：生态更封闭，存在提取方案（hook / 逆向协议类），但不安全，封号、隐私泄露、协议随时失效，还可能踩个人信息保护和爬虫相关的法律红线。结论是不上。

## 两个不同的问题，别混

- **别人社群的信息提取**：咱们只是群成员，没有运营权限，没法让别人配合投稿，只能从聊天流被动捞，「反向沉淀」那招使不上。这是当前真正卡住、需要持续留意合适方案的点。
- **咱们自己社群的内容沉淀**：以后可试「投稿入口 / 待审区」，让内容主动流到 Alice 能读的载体，跟现有知识库的待审区分工能接上。但这是自己社群的玩法，待试，不是当前重点。

## 结论与下一步

当前没有合规又稳的现成方案，不硬上，硬上反而踩坑。整体挂起，持续留意两件事：飞书是否放开外部群权限、是否出现合规稳定的新路子（微信侧同理）。一旦出现，第一时间推进。
